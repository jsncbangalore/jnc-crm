# JNC-CRM Production Go-Live Deployment Guide (Hostinger & Supabase)

This runbook documents the clean production deployment of JNC-CRM using **Hostinger Hosting** for the web frontend (`admin.jsnc.co.in`), a dedicated backend API service (`api.jsnc.co.in`), and a **fresh Supabase database instance** (`aybysdzuwwtqhnzhgiwp`).

> [!IMPORTANT]
> **Safety Principle**: The old Supabase project (`hbzlelktcfagwvmyusvw`) remains untouched as an immutable backup. Zero schema alteration or migration risks occur on existing databases.

---

## 1. Create the API Subdomain

> [!NOTE]
> Historical analysis indicates the old site operated frontend-only on `admin.jsnc.co.in` without a hosted API (`api.jsnc.co.in` did not exist in DNS). Creating and resolving `api.jsnc.co.in` is a mandatory first step.

1. **Create Subdomain in hPanel**:
   - Log in to Hostinger hPanel -> **Websites** -> **Domains** -> **Subdomains**.
   - Enter `api` under Subdomain name (creates `api.jsnc.co.in`).
2. **Enable SSL**:
   - In hPanel -> **Security** -> **SSL**, request Let's Encrypt / Hostinger SSL for `api.jsnc.co.in`.
3. **Wait for DNS Propagation**:
   - Allow a few minutes for local and global DNS record propagation.
4. **Verify DNS Resolution**:
   - Run the following command from your local machine:
     ```powershell
     nslookup api.jsnc.co.in
     ```
   - Confirm `nslookup` returns an IP address and does not return `Non-existent domain` before proceeding.

## 2. Deployment Architecture Options

### Option A: Hostinger Node.js Web App Feature
If your Hostinger plan includes the **Node.js Web App** manager:
1. Navigate in hPanel to **Websites** -> **Manage** -> **Node.js**.
2. Select **Node.js 20.x LTS**.
3. Application Root: `/api` (or designated directory).
4. Entry file: `start_server.js`.
5. Environment Variables:
   - Import environment variables generated by `npm run host:env` (`C:\dev\jnc-secrets\hostinger.env`).
   - Do NOT specify `PORT` (Hostinger assigns `PORT` dynamically to the process).
   - Delete `C:\dev\jnc-secrets\hostinger.env` off disk after importing.

### Option B: External Node Host / VPS (If Hostinger Plan Lacks Node.js)
If your Hostinger shared/cloud plan does not include the Node.js Web App manager:
1. Provision a small Linux VPS (e.g. Hostinger VPS, DigitalOcean, Linode) or managed Node platform (e.g. Render, Railway).
2. In Hostinger **DNS Zone Editor**, point the `A` record for `api.jsnc.co.in` to the IP address of your VPS/Node host.
3. Web frontend remains hosted on Hostinger (`admin.jsnc.co.in`).
4. **Exact Environment Variables for Node Host**:
   ```ini
   NODE_ENV=production
   DATABASE_URL=postgresql://postgres.aybysdzuwwtqhnzhgiwp:<PASSWORD>@aws-0-ap-south-1.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=5
   JWT_SECRET=<STRONG_64_CHAR_HEX_SECRET>
   JWT_REFRESH_SECRET=<STRONG_64_CHAR_HEX_SECRET>
   ENCRYPTION_KEY=<STRONG_32_BYTE_BASE64_KEY>
   FRONTEND_URL=https://admin.jsnc.co.in
   ALLOWED_ORIGINS=https://admin.jsnc.co.in
   TRUST_PROXY=1
   EMAIL_FROM=noreply@jsnc.co.in
   ```
5. **Exact Application Start Command**:
   ```bash
   npm install --omit=dev
   node start_server.js
   ```

## 3. Database Connection & Pooler Configuration

For the live Supabase project (region `ap-south-1`, pooler host `aws-0-ap-south-1.pooler.supabase.com`):

- **DATABASE_URL (Runtime)**:
  `postgresql://postgres.aybysdzuwwtqhnzhgiwp:<PASSWORD>@aws-0-ap-south-1.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=5`
  - Port **6543** (Transaction Pooler with PgBouncer mode enabled).
  - Connection limit **5** (`connection_limit=5`) prevents API connection starvation.
- **DIRECT_URL (Local Migrations Only)**:
  `postgresql://postgres:PASSWORD@db.aybysdzuwwtqhnzhgiwp.supabase.co:5432/postgres`
  - Port **5432** (Direct Session Connection). Required locally for `npx prisma migrate deploy`.
  - **Not required by NestJS API at runtime.**

## 4. Local Build, Migration & Release Packaging

Run the automated preparation pipeline from your local repository (`C:\dev\jnc-crm`):

```powershell
# 1. Preflight database health check
npm run db:preflight-live

# 2. Deploy database migrations over DIRECT_URL
npx prisma migrate deploy

# 3. Check Prisma model field usage across live scripts
npm run check:prisma-fields

# 4. Generate Hostinger production env secrets file
npm run host:env

# 5. Build production release archives
npm run release:pack
```

`npm run release:pack` generates two release archives in `deploy-release/`:
- `deploy-release/jnc-api-bundle.zip` (Backend API bundle with entry file `start_server.js`)
- `deploy-release/jnc-web-dist.zip` (Frontend Web distribution + production `.htaccess`)

## 5. Deployment Execution

### A. Deploy API Bundle to `api.jsnc.co.in`
1. Extract `jnc-api-bundle.zip` to the API root folder.
2. Configure environment variables in Hostinger Node.js UI using `C:\dev\jnc-secrets\hostinger.env` (generated via `npm run host:env`), then delete `hostinger.env` off disk.
3. Run standard package installation: `npm install --omit=dev`.
4. Entry file: `start_server.js`. Start or restart the application.

### B. Deploy Web Bundle to `admin.jsnc.co.in`
1. Extract `jnc-web-dist.zip` into `public_html` of `admin.jsnc.co.in`.
2. Verify `.htaccess` is present for SPA routing and security header enforcement.

After API and Web deployment:

1. **Run Live Verification**:
   ```powershell
   npm run verify:live -- --web https://admin.jsnc.co.in --api https://api.jsnc.co.in
   ```
2. **Platform & Company Setup Flow**:
   - Platform Admin signs in at `https://admin.jsnc.co.in/platform/login`.
   - Platform Admin creates client company "JNC Test".
   - Platform Admin creates initial Company Admin user for "JNC Test".
   - Company Admin logs in and creates tester accounts for team members.
3. **Dual-Network Rate-Limit Check**:
   - Submit one invalid login attempt from mobile (Cellular Data) and one from PC (Wi-Fi).
   - Inspect `X-RateLimit-Remaining` headers to verify counters decrement independently (confirming `TRUST_PROXY=1`).

## 7. Database Backups & Windows Task Scheduler Setup

Because Supabase free tier does not include automatic point-in-time recovery, local backups via `pg_dump` are mandatory.

### A. Install PostgreSQL Client Tools (pg_dump)
1. Download the EDB PostgreSQL Windows Installer: `https://www.postgresql.org/download/windows/`
2. Run installer, uncheck PostgreSQL Server and pgAdmin, select **ONLY "Command Line Tools"**.
3. Add `C:\Program Files\PostgreSQL\17\bin` to System `PATH`.

### B. Execute Manual Backup
```powershell
npm run db:backup
```
Generates timestamped SQL dump in `C:\dev\jnc-secrets\backups\jnc-backup-YYYY-MM-DD-HHmmss.sql`.

### C. Weekly Automated Windows Task Scheduler Task
1. Open **Task Scheduler** on Windows (`taskschd.msc`).
2. Click **Create Basic Task** -> Name: `JNC-CRM Weekly Database Backup`.
3. Trigger: **Weekly** (every Sunday at 02:00 AM).
4. Action: **Start a program**.
   - Program/script: `powershell.exe`
   - Add arguments: `-ExecutionPolicy Bypass -Command "cd C:\dev\jnc-crm; npm run db:backup"`

## 8. Rollback Procedure

Because the old live site never had a hosted API (`api.jsnc.co.in` did not exist in DNS), rollback is straightforward and low-risk:

1. **Restore Web Frontend**: In Hostinger File Manager, restore the original web files in `public_html` of `admin.jsnc.co.in` from `web-backup-pre-cutover.zip`.
2. **Revert DNS / Subdomain**: If needed, remove or adjust the DNS record for `api.jsnc.co.in`.
3. **Old Database Intact**: The old Supabase project (`hbzlelktcfagwvmyusvw`) remains untouched throughout. The site immediately resumes operating in its previous pre-cutover state.
